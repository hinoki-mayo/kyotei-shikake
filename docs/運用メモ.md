## 基本の考え方

- モデルの確率より、市場(オッズ)の確率の方が正確。モデル単体で「割安な目」を探しても勝てない(期待値1以上の3連単は回収率36%)。
- 勝てるのは「市場がいつも同じ方向に間違える条件」だけ。
- 回収率 ≒ 0.75 × 実際の確率 ÷ 市場の見立て。**実際÷市場が1.33倍を超えないとトントンにならない**。
- 市場の見立ては3連単オッズから逆算(1÷オッズを正規化して足す)。3連単は大穴が買われすぎるので、インは全体に少し低め、外は高めに出る。
- 3連単の**3着の見立ては市場がほぼ正確**(どの特徴でも実際÷市場が1.00前後)。ズレは1着・2着にある。だから基本は2連単。
- 締切2〜9分前のオッズは、締切までにインの頭の目へお金が流れ込んで大きく下がる(例: 1-3 が 15.3倍→確定9.8倍)。オッズで買う・買わないを決める条件はズレやすい。成績は確定の払戻で計算している。
- 説を立てた時の数字は、いくつか試した中から選んだ分だけ上振れしている(本番では何ポイントか下がる前提で見る)。

### 過去の確定オッズ(odds_hist)

- 市場の確率と実際の結果を月・年単位で比べるために、全レースの確定オッズ(3連単120通り+2連単30通り)を `data/odds_hist/YYYYMM.parquet` に貯める
- 1レース1行: `date`(YYYYMMDD) / `jcd` / `race` / `o3`(120個、`bet.ODDS_ORDER` の順) / `o2`(30個、1-2,1-3,…,6-5の順)。枠番キーで、売っていない目はNaN。両方取れなかったレースは空配列(取り直さない)
- 取得は GitHub Actions「過去オッズ取得」(開始日・終了日を入れて実行)。`scripts/fetch_odds_hist.py` を使う。他の処理とは別グループ(`odds-hist`)
- 1リクエストごとに1秒空けるので、1日(約150レース)で約5分。1回の実行(約5.5時間)で約2か月分。取れなかったレースは記録せず、同じ期間でもう一度流せば続きから取れる(20レース続けて取れないと打ち切る)

  v1案: 自信度＝別期間での推定回収率(少数は75%へ割り引き)、100%超の最高を採用、それ以外は見送り。最初は立説で並走。

## シナリオの木・自信度・決裁者(10/16〜17)
- 組織図はシナリオの木: ①決裁 → ②イン逃げ/負け → ③誰が勝つか(頭のコース・インの級) → ④説(プラン) → ⑤絞り(★印)。
  各プランの買い目を頭の艇ごとの「提案」に分けて箱に入れる(scripts/org_tree.py)。
- 自信度＝箱の提案を確定オッズの過去データで精算した回収率を、件数が少ないほど親の箱へ寄せた値(50件で半々・一番上は75%)。
  表は scripts/org_eval.py で作る(data/org/confidence.json、今は6/1〜10/13)。
- 決裁者v1(立説中): 同じ頭の提案同士で一番自信度が高いものを上げ、採用線以上は全部採用(複数OK)。同点は予想÷市場の比が大きい方。
  別期間の確かめ: 全提案 89%・82% / 線95% 107%・92% / 線105% 129%(168件)・103%(302件) → 線105%。
  ただし105%で採用されるのはほぼ裏の穴の★印ありで、★印は両期間を見て選んだので有利さが混ざっている。
- 効かなかったこと: 予想÷市場の比の帯で自信度を細かくする(本予想・GBMどちらでも悪化)、
  他の説が手を挙げない時のイン(81%・91%)、確実なイン(80%以上で81〜86%当たるが当たり倍率が1倍未満で75〜83%)、
  「1日の上位N件」(同点のくじ引きを除くと97%前後。実際は当日の上位は分からないので線に置き換える必要がある)。
- 参加枠(本番と別): 自信のB級イン(91〜92%)、市場より強いイン(88〜89%)。イン頭の網の目では「市場より15pt以上強い」が効く(93〜98%)。
- 次: 2026年2〜5月(条件選びで一度も見ていない期間)で、★印・採用線を変えずに決裁者を確かめる。
- 注意: 自信度用の精算で、2連単と3連単が混ざる提案を2連単だけで精算していたミスがあった(10/16に修正済み)。
